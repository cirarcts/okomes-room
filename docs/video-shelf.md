# 動画の棚（Video Shelf）設計資料

自分で選んだYouTubeチャンネルの動画を、自分の決めたルールで並べて視聴する展示物の調査結果・設計・開発計画を記録します。データの追加方法は [content.md](content.md#動画の棚video-shelf) を参照してください。

## 目的

- YouTube公式のおすすめ（視聴履歴に基づくパーソナライズ）に依存せず、明示的に選んだチャンネルの動画だけを表示する。
- Google OAuthやYouTubeアカウントの登録チャンネルとの同期は行わない。チャンネルはGit管理の設定ファイルで手動管理する。
- 動画はダウンロード・保存せず、YouTube公式の埋め込みプレイヤーで再生する。広告・再生制限・プレイヤー機能を回避しない。
- 将来的には独自ルールでの連続再生（エンドレス再生）へ発展させる。

## Phase 0：技術調査（2026-11-16）

YouTubeの公式文書（[Developer Policies](https://developers.google.com/youtube/terms/developer-policies)、[Required Minimum Functionality](https://developers.google.com/youtube/terms/required-minimum-functionality)、[Developer Policies Guide](https://developers.google.com/youtube/terms/developer-policies-guide)、[Branding Guidelines](https://developers.google.com/youtube/terms/branding-guidelines)）を確認した。規約は改定されるため、Phase 2以降の着手時に再確認する。

### 取得方式の比較

| 方式                                | 判定     | 理由                                                                                                                                                                                                                                                                                                                             |
| ----------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| YouTube Data API v3（APIキー）      | 要確認   | 技術的には最適（`playlistItems.list` でアップロード一覧を低コストに取得できる）。ただし **III.E.2** に「同じコンテンツオーナーのチャンネル以外のAPI Dataを集約しない／異なるコンテンツオーナーのAPI Dataを組み合わせない」趣旨の条項がある。分析データ向けの条項とも読めるが、文言上は複数の作者の新着をまとめた一覧が該当しうる |
| 公開RSS / Atomフィード              | 採用せず | 公式ドキュメントに記載がなく、継続性の保証がない（2026年にも404の報告がある）。III.I.14は「YouTube API Services以外の技術でAPI Dataを取得しない」、III.E.6はスクレイピングを禁止しており、RSSがこれらに当たるかは不明確                                                                                                          |
| 動画IDの手動管理 + 公式埋め込み     | **採用** | APIからデータを取得しないため、データ集約・保存の条項の対象にならない。自分で選んだ動画を埋め込むのは公式に想定された使い方                                                                                                                                                                                                      |
| Astroのビルド時取得・GitHub Actions | 保留     | 取得方式（Phase 2）が決まってから検討する                                                                                                                                                                                                                                                                                        |

### Data APIを使う場合の制約（Phase 2の判断材料）

- **データ保持（III.E.4）**：APIキーで取得した非認可データも、保存は30日以内。それまでに削除するか再取得する。定期ビルドが30日以上失敗した場合も古いデータを残さない仕組みが必要。
- **最新性（III.E.4.e / h）**：保存データを現在の状態と一致させる努力義務がある。削除・非公開になった動画を表示し続けない。
- **認証情報（III.D.1.4）**：APIキーを公開リポジトリに含めない。GitHub Actionsのsecretsに保存し、ビルド時のみ使用する。
- **APIプロジェクト（III.D.3）**：1つのAPIクライアントにつきAPIプロジェクトは1つ。90日間使わないと失効する可能性がある（III.D.4）。
- **集約（III.E.2）**：チャンネルごとの棚に分ける（複数チャンネルを1つの一覧に混ぜない）か、[API Compliance Audit](https://support.google.com/youtube/contact/yt_api_form) で可否を確認してから実装する。
- **Made for Kids（III.E.4.j）**：埋め込む動画が子ども向けかどうかを確認し、該当する場合はトラッキングを無効にする義務がある。

### 埋め込みプレイヤーの条件

- 表示サイズは200×200px以上（16:9なら480×270px以上を推奨）。
- プレイヤーの前面に要素を重ねない。プレイヤーを改変・妨害しない（III.I.6）。
- 自動再生は、プレイヤーが表示され半分以上見えている場合のみ。同時に自動再生するプレイヤーは1つまで。
- 音声と映像を分離しない（III.I.7）。表示していないプレイヤーでのバックグラウンド再生をしない（III.I.9）。
- 再生ボタンのクリック以外の操作を、視聴の条件にしない。
- `Referer` を送る。`Referrer-Policy` で抑制しない（推奨は `strict-origin-when-cross-origin`）。
- サムネイル・タイトルは改変しない。YouTubeが提供元であることを明示する（III.F.2.1）。YouTube利用規約へのリンクを表示する（III.A.1）。
- 再生区間の指定（`start` / `end`）、次の動画への移動、ループ、シャッフルについては、確認した文書に明示的な記述はなかった。IFrame Player APIに用意された機能を使う範囲で、Phase 4・5の着手時に再確認する。

## Phase 1：推奨構成と実装（MVP）

### データ

- `src/content/video-shelf/channels.json`：表示対象のチャンネル（slug、チャンネルID、名前、カテゴリ、有効状態）。
- `src/content/video-shelf/videos.json`：手動で登録した公開動画（動画ID、チャンネルのslug、タイトル、公開日）。
- どちらもContent Collections（`file()` ローダー）とZodで検証する。IDは形式を検証するが実在は確認できないため、**YouTube上で確認したIDだけを記入する**（推測で作らない）。
- 動画はチャンネルをslugで参照する。チャンネル設定（優先度・カテゴリなど）は動画データと分けて持ち、取得方式を変えても再利用できる。

### 責務の分離

| 層           | 場所                                                                | 責務                                                          |
| ------------ | ------------------------------------------------------------------- | ------------------------------------------------------------- |
| 設定・データ | `src/content/video-shelf/`                                          | チャンネル設定と動画データ（Phase 2で動画の供給元を差し替え） |
| 表示ロジック | [src/lib/videoShelf.ts](../src/lib/videoShelf.ts)                   | 有効なチャンネルの抽出、重複排除、並び順、YouTubeのURL        |
| 画面         | [src/views/VideoShelfPage.astro](../src/views/VideoShelfPage.astro) | 一覧・再生ステージ・注記の静的生成                            |
| 再生         | 同ページ内の小さなスクリプト                                        | クリック時に公式プレイヤーを読み込む                          |

再生の状態は「選択中の動画」1つだけのため、Reactを使わずに実装した。キューや連続再生（Phase 4以降）で状態が増えた時点でReactアイランドへの移行を検討する。

### 再生の仕組み

- 初期表示は「下の棚から動画を選ぶと、ここで再生されます。」という案内のみで、動画は決めない。動画カードが押された時点で、プライバシー強化モード（`youtube-nocookie.com`）の埋め込みプレイヤーを読み込む。自動再生はこのユーザー操作の直後に限る。
- JavaScriptが無効な場合や修飾キー付きのクリックでは、YouTubeの視聴ページを開く。JavaScriptが無効な場合は再生ステージを表示しない。
- サムネイル画像は `i.ytimg.com` から直接読み込む（保存しない）。そのため、プレイヤーを読み込む前でもサムネイルの取得でYouTube（Google）への通信が発生する。ページ下部で説明している。

## Phase 2：新着の自動取得（ハイブリッド構成）

2026-11-16に「案D：チャンネル別の棚（API）＋手動のおすすめ棚」を採用した。比較した案は次のとおり。

| 案                            | 判断     | 理由                                                                                     |
| ----------------------------- | -------- | ---------------------------------------------------------------------------------------- |
| A. チャンネル別の棚（API）    | Dに含む  | III.E.2に抵触しないことが明確                                                            |
| B. 統合フィード（API＋審査）  | 見送り   | 審査結果を待つ必要があり、却下の可能性もある。統合フィードが必要になった時点で再検討する |
| C. 手動のまま＋補助スクリプト | 見送り   | 新着が自動で反映されない                                                                 |
| **D. A＋手動のおすすめ棚**    | **採用** | 自動化と、自分で選んで並べる体験を両立できる。手動の棚はAPI Dataではないため統合してよい |

### 画面構成

| 棚               | データ                                    | 並べ方                                       |
| ---------------- | ----------------------------------------- | -------------------------------------------- |
| おすすめ         | `videos.json`（手動）                     | チャンネルをまたいで公開日の新しい順         |
| チャンネルの新着 | `channelUploads` コレクション（自動取得） | **チャンネルごとに分けて**表示し、統合しない |

再生ステージは両方の棚で共有する。動画を選ぶまでは案内を表示し、タイトル・公開元・操作欄は最初の動画が選ばれた時点で表示する。

### 取得の仕組み

- [src/content.config.ts](../src/content.config.ts) の `youtubeUploadsLoader` が、ビルド時に [src/lib/youtubeUploads.ts](../src/lib/youtubeUploads.ts) を呼び出す。
- 取得手順と使用量（1回のビルドあたり）：
  1. `channels.list`（`contentDetails`）でアップロード再生リストIDを取得（50チャンネルごとに1ユニット）
  2. `playlistItems.list` で、チャンネルごとに種類別の再生リスト（動画・ショート・ライブ）から直近最大100本ずつ動画IDを取得（50本ごとに1ユニット、既定では1チャンネル最大6ユニット）。本数は `channels.json` の `uploadsPerKind` でチャンネルごとに変更できる（1〜500本）。2ページ目以降の取得に失敗した場合は、取得できたページまでを表示する。種類別に取得できなかったチャンネルは、アップロード再生リストから同じ本数を取得する（50本ごとに+1ユニット）
  3. `videos.list`（`snippet,status`）で詳細を取得（50件ごとに1ユニット）
  - 例：推しチャンネル10件から種類ごとに100本ずつ取得する場合、1ビルドで最大約121ユニット（1日の上限10,000ユニットに対して十分小さい）。管理人チャンネルの全件取得は別途加算する。
- 表示から除外する動画：削除・非公開・限定公開、埋め込み不可、子ども向け（Made for Kids）、配信中・配信予定、別チャンネルの動画。子ども向けの動画はトラッキング無効化の義務（III.E.4.j）があるため、当面は扱わない。
- タイトルとサムネイルはAPIの値を改変せずに使う。サムネイルURLは `https://i.ytimg.com/` のもののみ受け付ける。

### データ保持（30日ルール）への対応

- 取得結果は**Gitにコミットしない**。Astroのデータストア（`.astro/`、Git管理外）にのみ置き、ビルドのたびに破棄して取り直す。公開リポジトリの履歴に残すと、30日以内に削除できなくなるため。
- 公開サイトは毎日の定期デプロイで更新する（[deployment.md](deployment.md)）。
- 取得に失敗した場合はAPIのデータを持ち越さず、該当チャンネルに「取得できませんでした」と表示する。そのため、公開中のデータは常に直近の成功したビルドのものになる。
- **残るリスク**：デプロイそのものが30日以上止まると、公開中のページに古いAPI Dataが残る。GitHubの定期実行は、リポジトリに60日間動きがないと自動で無効になる点にも注意する。デプロイが失敗し続ける場合は、原因を直すか、`YOUTUBE_API_KEY` を外してデプロイし、API Dataを公開物から取り除く。

### 失敗時の扱い

| 状況                                                             | 結果                                                           |
| ---------------------------------------------------------------- | -------------------------------------------------------------- |
| `YOUTUBE_API_KEY` が未設定                                       | 取得を省略し、チャンネルの新着を表示しない（ローカル開発・CI） |
| 一部のチャンネルの取得に失敗                                     | そのチャンネルだけ「取得できませんでした」と表示               |
| `channels.list` / `videos.list` の失敗、通信エラー、想定外の応答 | 全チャンネルを取得失敗として表示。ビルドは成功させる           |

ログとエラーメッセージにはAPIキー（リクエストURL）を出力しない。

## Phase 3：表示ルール（種別と検索）

2026-11-16に、Phase 3の候補のうち「動画の種別ラベルと絞り込み」と「タイトル検索」を実装した。カテゴリ・手動優先度・並び替えは、登録チャンネルが1つで効果が小さいため、チャンネルが増えて必要になった時点で追加する。チャンネル単位のON/OFFは `enabled` で対応済み。

### 動画の種別

2026-11-17に、YouTubeの「動画」「ショート」「ライブ」タブと同じ分類になるよう、種類別の再生リストによる判定を追加した。長さによる推定では、Shortsが「投稿動画」の棚に混ざっていたため。あわせて、長さで分ける「短い動画」（`short`）の種別は廃止した。

#### 種類別の再生リスト（基本の判定）

チャンネルID（`UC…`）の先頭2文字を置き換えた再生リストを、`playlistItems.list` で取得する。実装は [src/lib/youtubeUploads.ts](../src/lib/youtubeUploads.ts) の `KIND_PLAYLISTS`。

| 再生リストID | YouTubeのタブ | 付ける種別 |
| ------------ | ------------- | ---------- |
| `UULF…`      | 動画          | `regular`  |
| `UUSH…`      | ショート      | `shorts`   |
| `UULV…`      | ライブ        | `live`     |

- 「動画」タブにあるプレミア公開作品は `liveStreamingDetails` を持つが、配信として扱わない。
- 該当する動画がない種類の再生リストは存在せず、404が返る。これは「0件」として扱う。
- 2026-11-17時点の登録チャンネルで、3種類の件数の合計がアップロード再生リストの件数と一致すること、ShortsがYouTubeのショートタブと同じ並びになることを確認した。
- **この接頭辞は公式ドキュメントに記載がない**。公式APIの応答だけを使うためAPI以外の手段によるデータ取得（III.I.14）には当たらないが、予告なく使えなくなる可能性がある。404以外で失敗した場合と、3種類とも取得できなかった場合は、そのチャンネルだけ下記の推定に戻す。

#### 公式データからの推定（取得できなかった場合）

アップロード再生リスト（`UU…`）から同じ本数（既定で直近100本）を取得し、[src/lib/youtubeUploads.ts](../src/lib/youtubeUploads.ts) の `resolveKind` で分ける。Shortsは判定できないため、通常の動画に含まれる。

| 種別                     | 判定方法                                       | 補足                                                         |
| ------------------------ | ---------------------------------------------- | ------------------------------------------------------------ |
| 配信・プレミア（`live`） | `videos.list` の `liveStreamingDetails` がある | 配信のアーカイブとプレミア公開は、公式データでは区別できない |
| 通常（`regular`）        | 上記以外（長さが不明な場合を含む）             | カードにはラベルを付けない                                   |

- `/shorts/` URLのリダイレクトでShortsを見分ける方法は、API以外の手段によるデータ取得（III.I.14）に当たるため採用しない。
- `videos.list` の `part` に `contentDetails,liveStreamingDetails` を加えた。使用量は1回1ユニットのまま変わらない。
- 手動で登録した「おすすめ」の動画は、APIの詳細を結び付けない（チャンネルをまたぐ統合になるため）。種別は `videos.json` の任意項目 `kind` で指定でき、省略すると「未取得」として扱う。
- 種別と長さはサムネイルに重ねず（サムネイルの改変にあたるため）、タイトルの下に表示する。

### 検索と絞り込み

- 動画の棚のページ内で、おすすめとチャンネルの新着の両方を対象に絞り込む。追加の通信はない。
- 検索対象はタイトルとチャンネル名。全角・半角と大文字・小文字の違いを無視し、空白で区切ったすべての語を含む動画を表示する。
- 種別は「すべて／通常／Shorts／配信・プレミア」から1つ選ぶ。種別が未取得の動画は「すべて」のときだけ表示する。
- 該当件数は、おすすめと新着に同じ動画があっても1本として数える。棚ごとに該当がなければ「該当する動画はありません。」と表示する。
- JavaScriptが無効な場合は絞り込みの欄を表示しない（一覧はすべて表示される）。

## Phase 3（続き）：推しチャンネルの棚と管理人コーナー

2026-11-16に、チャンネルの追加に合わせて次を実装した。

| 項目               | 仕様                                                                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| カテゴリ           | `categories.json` に id・日本語名・英語名・表示順を定義する。チャンネルには複数指定できる。未定義の id はビルドエラーにする           |
| 優先度             | チャンネルの `priority`（数値、大きいほど上、省略時0、同じ値なら名前順）で棚の並びを決める。画面での並び替えは設けない                |
| カテゴリの絞り込み | 絞り込みの欄に追加する。動画は公開元チャンネルのいずれかのカテゴリと一致すれば表示する                                                |
| 横スクロールの棚   | チャンネルの新着をチャンネルごとに1列で並べ、横にスクロールする（スナップあり）。カードのリンクにフォーカスすると自動でスクロールする |
| 管理人コーナー     | `owner: true` のチャンネルを推しの棚から外し、ページ下部の「管理人のチャンネル（おまけ）」に小さめのカードで表示する                  |

- **棚の並びに「最近投稿があった順」は使わない**。チャンネルをまたいでAPI Dataを比べることになり、III.E.2の集約にあたるおそれがあるため。並び順は手動の設定（優先度・名前）だけで決める。
- 管理人コーナーには「代表作」と「新着」を並べる。
  - **代表作**：管理人チャンネルの全動画（最大1,000本）を取得し、`videos.list` の `statistics.viewCount` が多い順に上位5本を選ぶ。種別は問わない。カードに視聴回数（例：「1.2万回視聴」）を表示する。視聴回数が非表示の動画は対象外。
  - **新着**：同じく取得した動画のうち、公開日の新しい順に種類（動画・ショート・ライブ）ごとに最大100本（`uploadsPerKind` で変更可）。分類を個別に指定した動画はこの範囲外でも表示する。
  - 管理人自身のチャンネル内での並べ替えなので、集約の制限（III.E.2）には当たらない。視聴回数をそのまま並び順と表示に使い、独自の指標は計算しない。
  - 視聴回数は統計情報で、保存は30日まで（III.E.4.b）。ほかのAPI Dataと同じく、ビルドごとに取り直しGitには保存しない。
  - 使用量は、管理人チャンネルの動画50本ごとに約2ユニット（`playlistItems.list` と `videos.list`）。検索API（`search.list`、1回100ユニット）は使わない。
  - 管理人チャンネルの動画は `videos.json`（おすすめ）に登録しない。登録した場合はビルドを止める。
- 再生ステージは初期表示で動画を決めないため、管理人の動画が先頭に出ることはない。
- 絞り込み中は、該当する動画が1本もない棚（取得失敗の棚を含む）を隠す。

## Phase 4：再生機能（前へ・次へ／棚単位のキュー／連続再生）

2026-11-16に実装した。再生の制御は [src/lib/videoShelfPlayer.ts](../src/lib/videoShelfPlayer.ts)、キューの計算は [src/lib/videoQueue.ts](../src/lib/videoQueue.ts)、IFrame Player APIのラッパーは [src/lib/youtubePlayer.ts](../src/lib/youtubePlayer.ts)。状態は「キュー・今の動画・再生できない動画」程度のため、Reactは使わず素のTypeScriptで実装した。

| 項目                   | 仕様                                                                                                                                                                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| キューの範囲           | 押したカードがある**棚の中だけ**（おすすめ、各チャンネルの新着、代表作、管理人の新着）。チャンネルをまたがないので、III.E.2（集約）の懸念がない                                                                                                         |
| 前へ・次へ             | 棚の並び順で移動する。再生できない動画と、絞り込みで外れた動画は飛ばす（折りたたみ中の動画は飛ばさない）。端ではボタンを無効にする。広い画面（`lg` 以上）ではプレイヤーの左右、狭い画面ではプレイヤーの下に置く（2026-11-23に変更。見つけやすさのため） |
| 連続再生               | 常にON（2026-11-23にスイッチを廃止）。動画が終わると同じ棚の次の動画へ進む。自動で再生する条件（下記）は変わらない                                                                                                                                      |
| 自動で次を再生する条件 | プレイヤーの半分を超えて見えていて、かつタブが表示中のときだけ `loadVideoById` で再生する。それ以外は `cueVideoById` で準備だけして、ユーザーの操作を待つ                                                                                               |
| 再生できない動画       | `onError` を受けたらカードに「再生できません」と表示し、理由別のメッセージを出す。次の再生できる動画へ進む                                                                                                                                              |
| 操作欄                 | 前へ・次へを含め、プレイヤーには重ねない。再生方法と繰り返しのスイッチは再生ステージの下に置く。最初の動画が選ばれるまでは表示しない                                                                                                                    |

### 規約上の判断

- APIから次の動画を再生することは、RMFの「自動再生」にあたるとみなす。そのため、「半分を超えて見えている」という条件を守る。タブが非表示の場合も自動で再生しない（バックグラウンド再生の禁止 III.I.9）。
- ブラウザに自動再生を止められた場合（`onAutoplayBlocked`）は、メッセージを出して操作を待つ。
- 動画の切り替えには、文書化されたメソッド（`loadVideoById` / `cueVideoById`）だけを使う。プレイヤーの改変や、関連動画の非表示はしない。
- プライバシー強化モード（`youtube-nocookie.com`）のiframeでIFrame APIが使えるかは、公式文書に記載がない。2026-11-16に、`onReady`・`onStateChange`（終了の0を含む）・`onError`・`cueVideoById`・`loadVideoById` が動くことを確認した。動かなくなった場合も、iframe自体は通常の埋め込みとして再生できる（前へ・次へは、iframeの作り直しで動く。連続再生とエラー表示は使えなくなる）。

### エラーコードの扱い

| コード   | 意味                       | 表示                               |
| -------- | -------------------------- | ---------------------------------- |
| 100      | 削除・非公開               | 削除されたか、非公開になっている   |
| 101・150 | 埋め込みが許可されていない | サイト内での再生が許可されていない |
| 153      | Referer がない             | プレイヤーの設定エラー             |
| 2・5     | パラメータ不正・再生エラー | 再生できなかった                   |

## Phase 5.1：ランダム再生と繰り返し

2026-11-23に実装した。再生順の計算は [src/lib/videoQueue.ts](../src/lib/videoQueue.ts) の `shuffleQueueKeys`・`findFirstPlayable`、画面の制御は [src/lib/videoShelfPlayer.ts](../src/lib/videoShelfPlayer.ts)。状態が「再生方法・繰り返し・1周分の再生順」だけ増えたため、引き続きReactは使わない。

| 項目           | 仕様                                                                                                                                                                   |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 対象           | Phase 4と同じく、押したカードがある**棚の中だけ**。チャンネルをまたいでシャッフルしない（III.E.2）                                                                     |
| 再生方法       | 「棚の順」「ランダム」から選ぶ。初期は「棚の順」                                                                                                                       |
| ランダム       | 押した動画を先頭にして、棚の残りの動画をシャッフルした順に再生する（Fisher–Yates）。1周の中で同じ動画は1回だけ。再生中に切り替えた場合は、今の動画を先頭にして混ぜ直す |
| 繰り返す       | ONなら、棚の最後で最初に戻る。ランダムでは混ぜ直してから戻り、直前の動画が続けて再生されないようにする（再生できる動画が1本だけの場合はその動画を繰り返す）            |
| 前へ           | 今の再生順（ランダムでは今の周）の中で戻る。周をまたいでは戻らない                                                                                                     |
| 位置の表示     | ランダム中は「ランダム 3 / 23」のように、今の周の中での位置を示す                                                                                                      |
| 飛ばす動画     | Phase 4と同じく、再生できない動画と絞り込みで外れた動画を飛ばす                                                                                                        |
| 設定の保存     | 保存しない。ページを開き直すと初期値（棚の順・繰り返しOFF）に戻る                                                                                                      |
| 自動再生の条件 | 変更なし（半分を超えて見えていて、タブが表示中のときだけ）。繰り返しで終わりがなくなるが、条件を満たさないときは準備だけしてユーザーの操作を待つ                       |

## Phase 5.4：手動プレイリスト（全編・区間）

2026-11-23に実装した。データは `src/content/video-shelf/playlists.json`（書き方は [content.md](content.md#プレイリストplaylistsjson)）、変換と検証は [src/lib/videoPlaylist.ts](../src/lib/videoPlaylist.ts)。引き続きReactは使わない。

| 項目             | 仕様                                                                                                                                                                                           |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 表示場所         | 動画の棚のページの「おすすめ」の上に「プレイリスト」の見出しを置き、プレイリストごとに横スクロールの棚を並べる。再生ステージ・再生方法・繰り返しは他の棚と共通                                 |
| データ           | 動画ID・チャンネル・タイトル・区間・メモをすべて手動で記入する。APIのデータ（新着の詳細）は結び付けない                                                                                        |
| 規約上の判断     | チャンネルをまたいで並べるが、「おすすめ」と同じく手動のデータだけで作るため、API Dataの集約（III.E.2）にはあたらないと判断した。タイトルは改変せず、メモは別の行に表示する                    |
| 区間の再生       | IFrame APIの `loadVideoById` / `cueVideoById` のオブジェクト形式（`startSeconds` / `endSeconds`）と、埋め込みの `start` / `end` パラメータ（最初にiframeを作るとき）を使う。どちらも公式の方法 |
| キューの項目     | 項目のキーで区別する。区間のない項目は動画IDそのもの、区間の項目は `動画ID@開始-終了`（秒）。同じ動画の別の区間を、別の項目として前へ・次へ・ランダムの対象にできる                            |
| 再生できない動画 | 印は動画IDごとに付け、同じ動画の別の区間もあわせて飛ばす                                                                                                                                       |
| 次へ進む条件     | 終了（0）のイベントで次へ進む。ただし、読み込み後に再生（1）を始めた項目の終了だけを扱う。区間の終了直後に同じ動画の別の区間を読み込むと、余分な終了のイベントが届き2つ先へ進んでしまったため  |
| JavaScript無効時 | カードのリンクはYouTubeの視聴ページを開き、区間の項目は開始位置（`&t=秒s`）から開く                                                                                                            |
| 表示             | カードに「全編」「区間」のラベルと区間（例：`12:30〜18:45`）、メモを表示する。種別は持たないため、種別の絞り込みでは「すべて」のときだけ表示する                                               |

## チャンネル別の棚と過去動画

- チャンネルごとに「投稿動画」「配信アーカイブ・プレミア」「Shorts」を公開日の新しい順に表示する。分類はYouTubeの「動画」「ショート」「ライブ」タブに合わせ、種類ごとに直近最大100本を取得する（[動画の種別](#動画の種別)）。本数は `channels.json` の `uploadsPerKind` でチャンネルごとに変更できる。`shorts` はYouTube Shorts。
- 自動の分類を上書きしたい動画や、取得範囲より古い動画を個別に表示したい場合は、`channels.json` の `videoKinds` に動画IDと種別を登録する。通常は登録しなくてよい。直近の取得範囲外でも `videos.list` で詳細を取得し、公開元と表示条件を満たした動画に分類を適用する。各棚には、YouTubeのチャンネルの該当タブ（動画・ライブ・Shorts）へのリンクを置き、取得範囲より古い動画へ案内する。
- 各棚は最初の4本を表示する。「過去の動画を見る（残りN本）」を押すたびに12本ずつ追加し、すべて並べるとボタンが「過去の動画を閉じる」に変わって、YouTubeの該当タブへのリンクが現れる（閉じると最初の4本に戻る）。カードは取得済みの全件をHTMLに出力して表示だけを切り替えるため、追加の通信や重複は起きない。サムネイルは遅延読み込みのため、並べるまで取得しない。検索や絞り込みでは取得済みの全動画から一致するカードを表示する。JavaScript無効時は最初から全件を表示する。前へ・次へと連続再生の対象は、表示件数に関係なく同じ棚の取得済みの全動画（絞り込み中は一致した動画）。「過去の動画を見る」で開いていない動画を再生するときも棚は開かず、再生ステージの下のタイトルと位置（例：「5 / 100」）で示す。
