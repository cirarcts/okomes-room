# okomeのおへや
## デザイン・基本設計仕様 Ver.1.0

**英語名：** okome's Room
**キャッチコピー案：** 好きなものを、好きなだけ。
**開発形態：** 個人制作・公開Webサイト
**ステータス：** 基本方針確定／詳細デザイン検討段階

---

## 1. プロジェクト概要

### 1.1 コンセプト

「様々な記録や作品、好きなものを自由に残し、自分自身を表現していくWebサイト」

管理者であるokomeが、音楽・ゲーム・プログラミング・技術的な検証・日常の発見など、ジャンルを限定せず、自分の興味や活動を自由に蓄積・公開する。

訪問者は、okomeのおへやを訪れ、展示された作品や記録を自由に見たり、触れたり、探索したりできる。

単なるブログやポートフォリオではなく、**個人の世界観を持った、インタラクティブなデジタル展示空間**を目指す。

### 1.2 基本思想

- サイトの主役は管理者自身の興味・記録・作品。
- 大衆向けの流行や閲覧数を優先せず、自己表現を重視する。
- 投稿頻度や制作スケジュールに義務を設けない。
- 新しい興味が生まれたら、自由に展示物や部屋を追加できる。
- 訪問者が見たいコンテンツを自分で選択できる。
- 推薦アルゴリズムによる不要な情報の押し付けは行わない。
- 自分自身が最もよく使い、仕様を理解しているサイトを目指す。
- デザインの独自性と実用性を両立する。

## 2. サイト全体の構成

### 2.1 メインサイト

**okomeのおへや / okome's Room**

おへや全体を表すトップページを用意する。

トップページには、各部屋への入口や最近追加した記録、展示物などを配置する。

実際の3D空間を歩き回る方式ではなく、通常のWebサイトをベースに、おへやらしい視覚的表現を加える。

### 2.2 各エリア

| エリア | 役割 |
|---|---|
| あしあと | 日常の記録、活動履歴、発見、考えたこと |
| 展示室 | 完成した作品、研究成果、インタラクティブな展示物 |
| アトリエ | 制作途中の作品、実験、試作品 |
| たからばこ | お気に入りの動画、音楽、資料、Webサイトなどの収集（追加候補） |

それぞれを独立したエリアとして構成しつつ、関連する記録や作品への相互リンクを可能にする。

各エリアは固定的な制作フローではない。例えば、アトリエを経由せずに直接展示室へ作品を追加してもよい。

## 3. デザインコンセプト

### 3.1 全体テーマ

**「夜の秘密基地のような、落ち着いた少し近未来的なおへや」**

自分の好きなものや作品、記録が少しずつ増えていく、居心地の良い個人空間。

### 3.2 デザインの優先順位

1. ダーク・落ち着いた秘密基地
2. ナチュラルで柔らかい雰囲気
3. ポップ・デジタル・近未来的な表現

基本は1を採用し、2で親しみやすさを確保し、3をアクセントとして取り入れる。

全体を派手なサイバーパンク調にはしない。

### 3.3 ビジュアルキーワード

- ダークネイビー
- チャコールグレー
- 間接照明
- 落ち着いたデジタル空間
- 趣味の秘密基地
- コレクション棚
- 控えめな発光
- マットな質感
- 少し近未来的なインターフェース
- 親しみやすい柔らかさ

### 3.4 避けたいデザイン

- 汎用的な企業サイトやブログテンプレートに見える構成
- 過剰なネオンや発光演出
- 装飾を優先して情報が読みにくくなる画面
- 3D操作が必須になる複雑なナビゲーション
- 常時動く派手なアニメーション
- 全展示室に同一の見た目を強制するデザイン

## 4. 配色・タイポグラフィ

### 4.1 暫定カラーパレット

以下は初期デザインを作るための候補であり、確定色ではない。

| 用途 | カラー候補 |
|---|---|
| メイン背景 | `#0D1521` |
| カード・パネル | `#182432` |
| 補助背景 | `#111C29` |
| メイン文字 | `#EAF0F5` |
| 補助文字 | `#9EAAB7` |
| デジタル系アクセント | `#72D4D0` |
| 暖色アクセント | `#E9B77D` |

シアン・ブルーグリーンは近未来感、アンバーは室内照明の温かみを表現する目的で使う。

アクセントカラーは多用せず、操作対象や重要な情報を識別するために利用する。

### 4.2 タイポグラフィ

- 日本語を主体とした読みやすいフォントを採用する。
- 英字のサイト名や補助ラベルには、少し個性を持たせてもよい。
- 本文は読みやすさを優先する。
- コードや数値、測定データには等幅フォントを必要に応じて採用する。
- 見出しと本文のサイズ差、余白によって情報の階層を表現する。

### 4.3 UIの質感

- 基本コンポーネントは適度な角丸を採用する。
- 解析用パネルでは直線的なデザインも許容する。
- 透明感・ガラス風表現は控えめに使用する。
- 明暗差によってコンポーネントの階層を表現する。
- 木目・紙・金属などの素材感は、必要な箇所に限定して用いる。

## 5. トップページの設計方針

### 5.1 基本レイアウト

**ヘッダー**

- サイト名・ロゴ
- 各部屋へのナビゲーション
- モバイル向けメニュー

**メインビジュアル**

- 「okomeのおへや」の世界観を表現する。
- 夜の趣味部屋・秘密基地を連想させる。
- イラストや背景装飾の採用を検討する。
- 画面全体を覆う大掛かりな3D空間にはしない。

**部屋への入口**

- あしあと
- 展示室
- アトリエ
- たからばこ（必要になった場合）

家具、棚、机、扉などを連想させるカードやパネルとして表現することを検討する。

**最近の更新**

- 新しい展示物
- 最近追加したあしあと
- 更新された作品

自分が公開した情報のみを表示し、外部サービスの推薦コンテンツは勝手に混在させない。

**フッター**

- サイトの説明
- 外部リンク
- 著作権表示など

### 5.2 操作方針

トップページでは世界観と探索の楽しさを優先する。

一方、展示室に入った後は、Webアプリとしての操作性・情報の読みやすさを優先する。

## 6. 各エリアのデザイン方針

### 6.1 あしあと

**テーマ：静かに積み重なる記録帳**

- 時系列での表示
- カテゴリ・タグによる分類
- 画像・動画・リンクを含む記録
- 過去の記録の検索・閲覧

投稿の種類によって表示方法を変更できる構成を目指す。

### 6.2 展示室

**テーマ：好きなものを体験できる場所**

サイトの中でも、特に独自性の高いエリア。

展示物ごとに専用のレイアウト、コンポーネント、デザインを実装できるようにする。

#### 最初に検討する展示物

**Kemper Rig Viewer**

- Kemper Profilerに特化した設定表示
- Rig名・アンプ・キャビネット・エフェクトなどの表示
- JSONによる設定データ管理
- 実機を連想させる専用UI
- YouTube動画や演奏音源との関連付け

デザインは黒・グレー・緑を基本に、精密なオーディオ機材の雰囲気を目指す。

**FF14 木人DPS Analyzer**

- 木人討伐の記録
- HP推移グラフ
- 複数ジョブの比較
- バースト区間の可視化
- 動画とグラフの連動

デザインはゲームの世界観を適度に反映しつつ、解析画面としての視認性を重視する。

**GT7 Telemetry Viewer**

- 車両ごとの走行データ
- 速度・回転数・走行位置の可視化
- 複数車両・ラップの比較
- PPだけでは判断できない車両性能の分析

デザインはモータースポーツのテレメトリ画面を参考に、ダークカラーと近未来的なパネルUIを取り入れる。

### 6.3 アトリエ

**テーマ：自由な制作・実験空間**

- 制作中のアプリ
- 試作した機能
- 実験的なUI
- 開発・検証の記録

必ずしも完成している必要はない。

新しいアイデアを試すこと自体を楽しめる場所とする。

### 6.4 たからばこ

**テーマ：好きなものを集める保管庫**

将来的な追加候補。

お気に入りの動画、音楽、Webサイト、資料などを収集・展示する。

カード、棚、コレクションケースなどを連想させる見た目を検討する。

## 7. サイト共通のUIルール

各展示室の独自デザインは許容するが、次の要素は共通化する。

- サイトの基本ナビゲーション
- トップページへ戻る操作
- モバイル対応
- 文字の可読性
- キーボード操作
- 基本的な余白・レイアウトルール
- エラーや読み込み状態の表示
- 動きを減らすOS設定への対応

### 7.1 アニメーション

控えめなアニメーションを基本とする。

- ホバー時の色・明度変化
- カードの軽い浮き上がり
- パネルの展開
- フェード
- 扉や引き出しを開く感覚を取り入れた演出

展示物そのもののUIについては、より自由な演出を採用してよい。

ただし、操作を妨げるアニメーションは避ける。

## 8. 技術構成（確定した基本方針）

| 項目 | 採用技術 |
|---|---|
| サイト基盤 | Astro |
| ビルド方式 | 静的サイト生成 |
| インタラクティブUI | React |
| 言語 | TypeScript |
| CSS | Tailwind CSS + 独自CSS |
| グラフ | Apache EChartsを第一候補 |
| 記録データ | JSON / Markdown / MDX |
| データ検証 | Zod |
| ソース・記録管理 | Git / GitHub |
| 公開方式 | 静的ホスティング |
| データ解析 | 必要に応じてローカルPython |
| Webバックエンド | 当面導入しない |
| 本番DB | 当面導入しない |

### 8.1 コンテンツ追加方式

展示室の表示機能とコンテンツデータの両方を、VS Codeなどの開発環境から管理する。

新しいコンテンツを追加するときは、定義済みスキーマに従ってJSONやMarkdownなどのファイルを作成する。

GitHubへ反映した後、自動ビルド・デプロイによってサイトを更新する。

### 8.2 将来の拡張

管理画面、データベース、外部API、サーバー処理などは、実際に必要性が生じた段階で導入を再検討する。

最初から採用することは前提としない。

## 9. 初期開発の範囲

### 最初に実装するもの

1. Astro + React + TypeScriptの開発環境
2. 基本的なデザインシステム
3. サイト共通ヘッダー・ナビゲーション
4. トップページ
5. 展示室の共通レイアウト
6. JSONなどから展示データを読み込む仕組み
7. 最初のKemper展示物の試作
8. レスポンシブ対応
9. 静的ビルドと公開フロー

### 初期段階では必須にしないもの

- FF14とGT7の完成版
- Web管理画面
- ユーザー認証
- 本番データベース
- FastAPIなどのバックエンド
- コメント・評価機能
- 3D空間による探索UI

### 完成の考え方

全展示室が揃った状態を初期完成とはしない。

**トップページが公開され、Kemperなどの展示物を一つ閲覧・操作でき、同じ仕組みで新しいコンテンツを追加できる状態**を最初の完成目標とする。

## 11. プロジェクトの最重要原則

**「好きなものを、好きなだけ。」**

特定のジャンルに縛られず、自分の興味を自由に収集・探究・表現する。

独自性を持たせるために複雑にするのではなく、自分が使って楽しいこと、訪問者が見て面白いことを大切にする。

機能・デザイン・技術構成は、サイトのコンセプトと実際の利用体験を優先して選択する。

サイトそのものが、時間をかけて少しずつ成長する作品になることを目指す。
